# M0 真实案例采集与冻结工作表

> 状态：`v0.1.0-frozen`，25 条受控重构案例已冻结
> 用途：把 2023—2024 年飞智真实事件整理成可追溯的 M1 评测案例
> 里程碑范围与通过门槛：见 [PROJECT_PROPOSAL.md](../../PROJECT_PROPOSAL.md#4-m0m1案例建设与可行性验证)

本文件先承接人工访谈与事实核对。信息补齐并通过事实复核后，再把案例转换为带版本的机器可读评测集。未填写、未复核或无法确认的内容一律保留为“待补充”，不得由 Agent 推测。

## 1. 证据与状态

每条案例必须标记一个证据状态：

- `真实业务事实`：用户在飞智任职期间亲历、能够说明来源的内容。
- `重构基线/估算`：根据真实经历重新估计的数据或过程。
- `目标门槛`：预先定义的里程碑要求。
- `实测结果`：未来基于冻结案例集、明确版本和评分规则得到的结果。

案例生命周期：

1. `draft`：仍在补充事实，不进入正式评测。
2. `fact_review`：业务事实已补齐，正在补原始证据或独立外部复核；若这些资源不可获得，可在严格证据边界下走受控重构降级门。
3. `frozen`：输入、标准答案、评分规则、证据和版本均已锁定，可进入正式评测。
4. `retired`：发现事实错误、知识失效或范围变化后停用；保留记录，不静默改写历史结果。

冻结后不得直接修改案例来提高成绩。必要变更必须产生新版本，并记录原因。

## 4. M1 首批覆盖清单

M1 冻结集至少 25 条，组卷时逐项核对：

- 三个事件各有 6—8 条核心案例。
- 至少 5 条越界、证据不足或必须转人工案例。
- 原始口语、同义改写和信息缺失均有覆盖。
- 简单、中等、困难案例均有覆盖。
- 每条案例只有一个主要评分意图，避免一题同时测试过多能力。
- 可回答案例有可定位的标准答案依据；不能确认的内容不设为正确答案。
- 硬升级案例明确触发信号和禁止动作。
- 同一基础事实生成变体时，保留共同来源和变体原因，避免把改写数量误当独立事实数量。
- 冻结时记录评测集版本、案例清单、事实评审者和冻结日期。
